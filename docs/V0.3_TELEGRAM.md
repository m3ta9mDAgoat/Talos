# Talos v0.3 — Telegram ingestion slice

## API actions

- `POST /api/v1/sources/{id}/test-access`
- `POST /api/v1/sources/{id}/import-history?limit=1000`
- `POST /api/v1/sources/{id}/sync?limit=250`
- `GET /api/v1/sources/{id}/messages?limit=100`
- `POST /api/v1/sources/{id}/parse-signals?limit=5000`
- `GET /api/v1/sources/{id}/signals?limit=100`

## Design notes

The raw archive is kept separately from normalized signals. Re-running a parser does not destroy the original Telegram message. Signal persistence is idempotent per strategy/source/message and updates an existing signal when the current stored Telegram revision changes.

Historical imports use a source-level message cursor so repeated imports advance through a channel instead of re-reading only the first batch. Latest-message sync is separate so recent signals can be captured while a large historical archive is still being backfilled.

Render Free is not treated as a reliable 24/7 listener. V0.3 therefore uses explicit sync. A persistent worker will later reuse the same ingestion functions on a VPS/local host without changing the source or strategy contracts.
