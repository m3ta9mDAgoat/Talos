# Talos v4.4.1 — Multi-asset OSINT + Mission Control

## What this package implements

This is an **upgrade to the existing Talos application**, not a separate prototype and **not an infrastructure migration**. Existing trading, Telegram replay, paper/live execution, research, strategy, Admin, and supplied helmet splash files are retained. Render is still the web runtime; Neon PostgreSQL is still the transactional store.

### Intelligence pipeline

1. A bounded collection cycle reads a fixed allowlist of public feeds and APIs.
2. Adapters: RSS/Atom, official Binance announcement HTML best-effort, GDELT DOC JSON (3 research queries), public GitHub repository releases, and optional SEC EDGAR company submissions by CIK.
3. Normalization includes XML/HTML cleaning, URL validation, date parsing, entity/asset keyword matching, event-type rules, rule-based ranking, source weighting, and same-headline clustering.
4. Event rows contain `first_seen_at`, `published_at`, `last_seen_at`, a content hash, source identity, symbols and event classification. `first_seen_at` is immutable.
5. Changed event text appends an **immutable revision** in `intelligence_revisions`. Unchanged feed observations produce no item write.
6. `intelligence_signal_links` records symbol overlap with Talos signals as **context only**, NOT evidence of causation.
7. The generic point-in-time `/features` endpoint reconstructs event rule scores from the last revision **observed by the supplied timestamp**; future edits do not leak into historical research features.
8. No service automatically places a trade because of OSINT. No paid API keys or brokerage withdrawal scopes are required.

### Sources (initial live adapters; availability depends on upstream providers)

- Official SEC press releases and optional company EDGAR watchlist (`OSINT_SEC_CIKS` + `OSINT_CONTACT_EMAIL`)
- Federal Reserve releases/speeches, ECB, EIA
- CISA cybersecurity advisories
- BBC world/business/technology/science
- Kraken blog, Coinbase incident status, Binance official announcements (HTML best-effort)
- GDELT world/macro, commodities/supply, cyber news queries
- GitHub public releases (configurable allowlist; defaults to Bitcoin, Ethereum and Solana repositories)

Each source reports its actual last attempt, last success, error and batch count. Provider blocks, rate limits, format changes and inaccessible feeds are recorded; no invented news is substituted.

Not included as claims of completed third-party integration: paid real-time financial terminals, unlicensed social media scraping, paid on-chain analytics, full commercial exchange announcements API integrations, semantic multilingual named-entity models, or guaranteed instant news delivery. Existing Telegram sources still work through their prior isolated system; private Telegram raw content is **not silently republished into public OSINT read endpoints**.

### API

All under `/api/v1/intelligence`:

| Method | Path | What it does |
| --- | --- | --- |
| GET | `/dashboard` | Compact paper, signal, job and high-priority snapshot. |
| GET | `/feed?category=crypto&hours=72&min_importance=55&limit=20` | Bounded/filterable public event feed with duplicate suppression and evidence metadata. |
| GET | `/events/{event_id}` | Source event, complete observed versions and linked signal IDs. |
| GET | `/features?symbol=BTC&hours=24&as_of=2026-10-09T15:00:00Z` | Point-in-time research-only indicators. |
| GET | `/sources` | Collector health for every registered adapter. |
| GET | `/summary` | 24-hour event counters and collector availability. |
| POST | `/collect` | Admin-session-protected manual collection (not required normally). |
| POST | `/sources/{key}/enabled?enabled=false` | Admin enable/disable. |
| POST | `/prune?days=90` | Admin manual prune of **unlinked** old intelligence only; never silent deletion of linked research evidence. |

`POST` Intelligence paths are covered by the pre-existing Talos Admin session middleware. GET reads return public-source data only.

### Dashboard

- Minimal metrics: **paper equity, open paper positions, signals in last 24h, high-priority OSINT events in last 24h**.
- OSINT is a first-class event/news feed even without a running algorithm.
- Distinct Intelligence screen: category, freshness, search and priority filters; headline source, evidence breakdown, symbols, source health and Admin-only collection controls.
- Operations strip shows real backend state and failed feeds; empty / degraded states are explicit.
- Browser polls dashboard every 90s, Intelligence source diagnostic table every 180s. Collection checks are source-interval based, not a fast DB poll. This is **not** a sub-second breaking news terminal.
- The original `talos-splash.png`, `talos-splash-2x.png`, and zoom code are preserved.

## Render + Neon deployment (upgrade in place)

1. **Download/unzip** this package. Its root contains `Dockerfile`, `backend/`, `frontend/`, `render.yaml`. Do **not** upload the ZIP as a single file to GitHub or nest it within an extra directory.
2. Back up your existing GitHub commit and record existing Render environment variables (do not paste or expose secrets). This change is additive and uses new `intelligence_*` SQLAlchemy tables. Old tables are not dropped.
3. From your local Talos repository root, copy these updated files over the current source (not into a subfolder); inspect with `git status` and `git diff --stat`; commit and push to the same GitHub repository.
4. Existing Render Free web service redeploys from GitHub. **Do not create a new paid service**. Keep the current Neon `DATABASE_URL` and `SECRET_KEY`. Keep `LIVE_TRADING_ENABLED=false` until independently audited.
5. Optional Render env variables: `OSINT_ENABLED=true`, `OSINT_INTERVAL_SECONDS=1800`, `OSINT_MAX_DB_BYTES=650000000`, `OSINT_GITHUB_REPOS=...`, `OSINT_SEC_CIKS=...` with `OSINT_CONTACT_EMAIL=...`. All are optional. Do not add keys for paid APIs.
6. Load `/health` and verify `database=ready`; `/api/public/build` should show `4.4.1`. Allow at least one minute for first OSINT cycle; visit the Intelligence page for individual source errors.
7. **Roll back** Render to the previous GitHub commit if build/runtime regresses. New intelligence tables are additive and need not be deleted for rollback.

### Zero-Spend / resource safety

- No new paid cloud products. No metered third-party data plans. No auto-upgrades.
- An OSINT storage guard checks `pg_database_size(current_database())` at most once each 6 hours and pauses new OSINT writes once configured threshold is reached or size cannot be verified. It does not block existing trading audit writes.
- Bounded per-provider fetch (max 1.2 MB), max 25 items per cycle per source, public allowlist, release feed windows, per-source SQL leases, failure isolation, limited SQL roundtrips, and collection delays.
- **Important:** neither this guard nor budget alerts can guarantee a $0 bill if you separately upgrade Neon/Render to usage-billed services. Remain on strictly free-only plans and verify provider account settings. Neon Compute quotas may still pause the free database, and Render Free may sleep or restart, causing gaps in collection.

### Troubleshooting

- Empty feed? Check `GET /api/v1/intelligence/sources`, allow first minute, and check source errors. If upstream blocks Render, switch off that source from Admin rather than rotating proxies or bypassing restrictions.
- `database=unavailable`? This is independent of the frontend; inspect Neon quota and Render logs, keep the older Talos data untouched.
- HTTP 428 on Collect/Toggle? Initialize the Admin once using your existing `SECRET_KEY`, then log in. This is expected access control.
- Failed Docker frontend stage? Inspect `npm install` / `npm run build` logs; do not label the release deployed until the error is resolved.

## Research integrity boundaries

- Observed sources are not facts established by Talos. A publisher can be mistaken. The numeric `importance` is a **heuristic queue rank**, not probability of a true event, price impact, or profitable trade.
- GDELT coverage is selective and may repeat syndicated reports. Symbols are cautiously extracted, with no automatic inference of bullish/bearish direction.
- `as_of` is used for point-in-time research. Never use a later revised event as if Talos knew it earlier.
- Existing live trading modules were not expanded or independently security audited as part of this OSINT upgrade. Leave them disabled until tested separately.

### Windows Git deployment helper

From the extracted release folder, run:

```powershell
.\deploy-windows.ps1 -RepoPath "C:\path\to\your\existing\Talos"
```

This refuses a dirty Git working tree, preserves `.env`, `.git`, skips `node_modules` and caches, and lists a diff. After reviewing the diff, commit and push manually. If you explicitly want the helper to commit and push on your behalf, add `-CommitAndPush`. Never run on the wrong repository directory.
